# Vercel + Unity WebGL deployment checklist

## Current status
The repository root can deploy as a static site. The site is currently a status page, not the game. The Unity starter source has not yet been compiled to WebGL, and this repository does not yet contain the Unity WebGL runtime output.

## Build in Unity
1. Install the matching Unity Editor version and Web Build Support.
2. Open the Unity project and build for Web.
3. Test the exported build with a local HTTP server (do not open index.html as file://).
4. Copy the actual generated build files into public/game/ and preserve the generated filenames.
5. Update the root page to load the actual Unity loader script, using the exact build filenames generated by Unity.
6. Test desktop and mobile browsers, including memory use, loading progress, touch controls and orientation.

## Vercel project settings
- Framework preset: Other
- Build command: empty
- Output directory: .
- Install command: empty

## Common issues
- A successful Vercel deployment only proves that static files were served; it does not prove Unity gameplay works.
- Never invent .wasm, .data or loader files.
- Unity WebGL memory requirements may exceed what some mobile devices can provide.
- If the game fails to load, inspect browser console errors, file paths, Content-Type headers and Unity's generated loader configuration.
- Large WebGL builds can exceed Git repository or deployment limits. Use a supported large-file/object-storage approach when needed.
